### Changed

- **The B-216 nonprod DSR alert receiver now targets the main Cloudflare account, fenced to its own Worker and D1 (#1678).** The owner decided on 2026-10-01 to stop depending on account 5128. Three `deploy_once` runs there failed at the first private deploy, and the last one (36943433367) classified the failure as an uncoded API rejection of the script upload. No new key is coming. The receiver therefore moves to account `6a1fc1c626fc2628823e60b9db01f5cd`, which also hosts production and staging, under the bounds already accepted for staging: dedicated names, cost of about US$1 at most, workers.dev disabled after use, and no production resource touched. The pinned pair is now Worker `corelink-dsr-b216-alert-receiver-6a` and D1 `corelink-dsr-b216-alert-receipts-6a`, kept in one module (`scripts/receiver-target.mjs`). That module refuses to load if either name drifts out of the dedicated namespace or onto a production or staging name (`corelink-prod*`, `corelink-api*`, `corelink-signup-worker`, `corelink-staging*`, `corelink-server`, `corelink-config-*`, `corelink-dsr-erasure*` and the other names declared in this repository). The route refuses any Worker or D1 name other than that pair, in its tracked config, its API paths and its Wrangler arguments. Each Cloudflare API request must match an allowlist: reads of the account, its script list and its workers.dev subdomain; reads of the receiver's own deployments, versions, secrets and subdomain; the one subdomain toggle; the exact-name D1 lookup; and queries against the one D1 UUID adopted in that run. Each Wrangler call must match one of six exact command shapes against the run's pinned temp config. The D1 is adopted by its exact name instead of a UUID frozen in source, because the lead creates it once on the shared account. The workflow now runs in the protected `staging` environment. It uses `STAGING_CF_WORKER_API_TOKEN` for Cloudflare and `STAGING_DSR_DLQ_ALERT_AUTH_TOKEN` as the receiver bearer, which is the same secret the signup-worker staging alert sender puts in its `Authorization: Bearer` header. It refuses to run unless `STAGING_CF_ACCOUNT_ID` equals the pinned account. The two-stage bootstrap path is removed: it pinned the account's whole Worker inventory, which cannot hold on a shared account, and its environment never had a credential. The token diagnostic's account fields are renamed `target_account_scope` and `workers_admin_on_target_account`. Every Wrangler failure diagnostic from #2877 is kept, and its fixtures were re-captured against the new target.
