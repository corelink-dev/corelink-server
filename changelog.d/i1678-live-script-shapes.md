### Fixed

- **The B-216 receiver route now reads Cloudflare's actual script and version shapes, and names the check that refused (#1678).** `deploy_once` run 37045137543 created the private receiver Worker and was then refused at `worker_initial_private_readback`; its receipt said only `route_failed_closed`. Read-only GETs on account 6a found two shape mismatches. First, the Workers script list gives `routes: null` for a script without routes (126 of 139 scripts), and the readback refused `null` as `worker_routes_ambiguous`. `null` now counts as zero routes, a missing field stays `unknown`, and any other non-array is still refused. The zero-ingress proof, which reads zone routes, custom domains and service routes directly, is unchanged. Second, the versions API carries `workers/tag` in the version's top-level `annotations`: 14 tagged versions had it there and none under `metadata.annotations`, which is where the route looked. The next stage would have found no tagged upload (`worker_uploaded_revision_ambiguous`), so the upload lookup, the candidate check and the route-owned-revision check now read the top-level field only. Refusals are also self-describing now. A readback refusal keeps its own code (`worker_routes_ambiguous`, …) in the deploy and exercise receipts, the log line and the cleanup entries, instead of `route_failed_closed`. When a successful read fails a shape check, the receipt names that read in `read_failure`, with the endpoint, HTTP status, no error codes and the new message class `unexpected_shape`. A retry on the D1 left by that run, which has the exact migration and its ledger, is adopted as `applied`, with no `d1 migrations apply` and only `SELECT` statements. Two review findings are fixed in the same change. First, the version to deploy is no longer picked from a version list by its SHA tag. On a same-SHA retry, a stale list holding only an older version with that tag let the route deploy the old version and report `deployed`. The route now takes the version IDs that Wrangler prints for its own `versions upload` and `versions secret put`. Both are stamped with a message carrying a per-run random nonce. The secret version must carry this run's tag, its message and the upload's script etag, and it is the exact ID that is deployed and read back. If either ID cannot be captured, the run is refused before activation (`worker_upload_version_unbound`, `worker_secret_version_unbound`, `worker_revision_not_this_run`). Second, the D1 schema check no longer rewrites string literals. It compares token lists in which literals and quoted identifiers keep every byte, and only keywords and bare identifiers are case-folded. A `GLOB` pattern that lost its brackets, or an uppercased event literal, is now `database_schema_drift` instead of an exact match.
