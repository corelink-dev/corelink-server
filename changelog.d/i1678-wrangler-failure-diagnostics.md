### Fixed

- **A failed B-216 receiver deploy now says why Wrangler failed (#1678).** Runs 36812580006 and 36934258883 both stopped at the first private `wrangler deploy` with `process_exit` and `unknown_cli_failure`. The route keeps Wrangler's output out of the receipt, and that pair is what it recorded for any failure whose output carried no `[code: N]` marker. Wrangler 4.141.0 was run with the route's exact argv against a local mock of the Cloudflare API. A WAF block page, a non-JSON response, a JSON rejection without an error code and a dropped connection all produced that same receipt. The classifier now adds `waf_block`, `malformed_api_response`, `network_failure` and `api_request_rejected` to its categories. The existing `first_deploy_required` category now also matches the message Wrangler 4.141.0 actually prints for `versions upload` on an absent Worker. Four bounded fields are new. `provider_error_codes` lists every numeric API error code in order, up to eight. `provider_failure_endpoint` is an allowlisted label for the first request Wrangler reported as failed, such as `worker_script` or `worker_service`. `provider_http_status` is the status Wrangler printed for a WAF or malformed response. `provider_progress` records whether Wrangler had reported the bundle or the upload before it failed. The receipt still never holds Wrangler's text, the request path, the account ID, a Ray ID or a token. Seven verbatim Wrangler 4.141.0 captures are kept as a test fixture, and each one classifies to a different tuple.
