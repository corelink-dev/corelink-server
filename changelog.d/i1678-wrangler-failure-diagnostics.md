### Fixed

- **A failed B-216 receiver deploy now says why Wrangler failed (#1678).** Runs 36812580006 and 36934258883 both stopped at the first private `wrangler deploy` with `process_exit` and `unknown_cli_failure`. The route keeps Wrangler's output out of the receipt, and that pair is what it recorded for any failure whose output carried no `[code: N]` marker. Wrangler 4.141.0 was run with the route's exact argv against a local mock of the Cloudflare API. A WAF block page, a non-JSON response, a JSON rejection without an error code and a dropped connection all produced that same receipt. The classifier now reads the diagnosis only from Wrangler's first error block: the first `✘ [ERROR]` banner at column 0 within the first 256 KiB of stderr, and the two-space-indented notes under it. Its message is matched exactly against the messages Wrangler 4.141.0 prints, giving `waf_block`, `malformed_api_response`, `network_failure` or `first_deploy_required`. Under an API-request banner, the API's own codes and messages give `authentication_failed`, `permission_denied`, `resource_not_found`, `rate_limited`, `invalid_configuration` or `api_request_rejected`. Any other banner gives `unknown_cli_failure`, as does output with no block in the window, which `provider_output_structure` marks as `no_structured_error` or `truncated`. No category or code is ever read from text outside a recognised block. That includes a later follow-up, such as whoami losing its connection after a code-10000 error, and a response body Wrangler echoes. The echoed body cannot pose as metadata because Wrangler indents every line of it. Four other bounded fields are new. `provider_error_codes` lists up to eight codes from the API-request block. `provider_failure_endpoint` is an allowlisted label for the request the block names, or `ambiguous_report` when two request notes cannot be told apart. `provider_http_status` is the status in a WAF or malformed-response request note. `provider_progress` records whether Wrangler printed its exact bundle line or the `Uploaded <fixed Worker>` line on stdout. Every pattern is linear and bounded; ten 4 MiB adversarial inputs each classify in well under the 1.5 s test bound. The receipt still never holds Wrangler's text, the request path, the account ID, a Ray ID or a token. Nine verbatim Wrangler 4.141.0 captures are kept as a test fixture, including a hostile response body and a follow-up connection loss.
