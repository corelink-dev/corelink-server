### Fixed

- **A failed B-216 receiver deploy now says why Wrangler failed (#1678).** Runs 36812580006 and 36934258883 both stopped at the first private `wrangler deploy` with `process_exit` and `unknown_cli_failure`. The route keeps Wrangler's output out of the receipt, and that pair is what it recorded for any failure whose output carried no `[code: N]` marker. Wrangler 4.141.0 was run with the route's exact argv against a local mock of the Cloudflare API. A WAF block page, a non-JSON response, a JSON rejection without an error code and a dropped connection all produced that same receipt. The classifier now reads the diagnosis from Wrangler's first error block only: the first `✘ [ERROR]` banner at column 0 of stderr and the two-space-indented notes under it. That block gives the category: `waf_block`, `malformed_api_response`, `network_failure`, `api_request_rejected`, `first_deploy_required` (now also matching the message Wrangler 4.141.0 actually prints) or an existing category. A later follow-up, such as whoami losing its connection after a code-10000 error, can no longer change it. Four bounded fields are new. `provider_error_codes` lists the first block's numeric codes, up to eight. `provider_failure_endpoint` is an allowlisted label for the request that block names. `provider_http_status` is the status in a WAF or malformed-response request note. `provider_progress` records whether Wrangler printed its exact bundle line or the `Uploaded <fixed Worker>` line on stdout. A response body that Wrangler echoes cannot pose as metadata, because Wrangler indents every line of it. Codes are never read from it. When two request notes appear they cannot be told apart, so the endpoint becomes `ambiguous_report` with no status. Every pattern is linear and bounded. Analysis reads at most 256 KiB: the head of stderr, the head of stdout for progress, and the tail of unstructured output. Each of ten 4 MiB adversarial inputs classifies in under 200 ms, where the previous patterns were quadratic. The receipt still never holds Wrangler's text, the request path, the account ID, a Ray ID or a token. Nine verbatim Wrangler 4.141.0 captures are kept as a test fixture, including a hostile response body and a follow-up connection loss.
