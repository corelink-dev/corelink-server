### Fixed

- **The one-command merge (`pre-merge-gate-check.sh --merge`) could not land any PR (B-315).** Its helper built a signed merge commit and pushed it straight to `main`, and branch protection (strict required checks, enforce_admins, linear history) declines every direct push. The helper now lands through the pull-request merge API with `sha=<gated head>` and `merge_method=squash`, keeping the allocation lock, the exact base/main/head capture and revalidation, and the allocator check on the exact `BACKLOG.md` blob bytes. It also refuses a head that does not contain current `main` before calling the API. After the merge it proves that the PR is MERGED and that the merge commit's only parent is the captured `main` and its tree is the head's tree; if that proof fails it exits 3 and the gate reports the merge as landed but unproven instead of calling it cosmetic. A new hermetic harness runs the real helper against a fake GitHub that declines pushes to `main`, covering the land, dry-run and refusal cases. The gate header no longer claims `required checks = []`.
