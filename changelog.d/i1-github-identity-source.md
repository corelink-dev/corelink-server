### Fixed

- **The GitHub identity now comes from one file, `config/github-identity.json`, after the org was recreated as `corelink-dev` (migration I1).** The old org was recreated, not transferred, so every repository has a new numeric ID. Before this change, `scripts/server_repository.py` and five scripts hard-coded the retired `HuGR-dev/corelink-server` name and ID `1232040291`, so they refused every run in the new repository. The resolver now reads the owner, the three repository names and their IDs from the identity file. It refuses an ID of `0` ("not read back yet"), a retired ID, and a historical owner (`HumanGuardrail`, `HuGR-Labs`, `HuGR-dev`) used as the current owner. In Actions it accepts only an exact `GITHUB_REPOSITORY` and `GITHUB_REPOSITORY_ID` pair, and a new `--require-github-context` flag exposes that check. The B-046 receipt builder, the B-102..B-108 context collector and packet verifier, the #2568 operator (including its `git ls-remote` URL) and the #1721 preflight now authorize through the resolver. The identity gate (`scripts/test_server_repository_identity.py`) now checks every tracked text file, not only nine suffixes, so the `.ps1` and `.mjs` files it missed are covered. It flags retired peer-repository names, retired numeric IDs and new current-owner literals, and it fails on any `.github/` repository-ID number that was not read back. It names stale or missing ledger rows, and it rejects an injected `HuGR-dev/corelink-server`. The 145 files that still carry a retired identity are listed in a shrink-only ledger, each with the PLAN work package that owns it. Mutation probes: all 13 planted defects turned their tests red, and a no-op edit stayed green.
