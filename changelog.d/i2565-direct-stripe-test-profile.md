### Changed

- **Close the direct-test pre-request refusal coverage gap found in PR #9.** Every refused credential now exercises all eight guarded harness entry points, including Starter price creation and both fixture archive methods, with an immediate zero-request assertion. The credentialless PR lane also removes each guard in a temporary workspace and requires the behavioral assertion to fail; the source verifier independently checks each guard and refused-key exercise.

- **The B-068 real Stripe profile now runs directly against Stripe TEST mode instead of the HuGR Wallet broker (#2565).** On 2026-10-02 the owner decided to run the isolated real-provider profile with a Stripe test key, because the Wallet token, base, reference and Starter price it hard-coded do not exist. `real-ignored-harnesses.yml` now passes `STRIPE_AUTH_MODE=direct-test`, the protected `STRIPE_SECRET_KEY_TEST` and `STRIPE_TEST_ACCOUNT_ID` to the `stripe` profile only. A live key is refused three times: the runner rejects anything that is not `sk_test_`/`rk_test_` (naming `sk_live_`/`rk_live_`) before Cargo starts; the harness's `StripeClientConfig::direct_test` and every harness client call refuse it before a request; and after authenticating, the harness requires the expected TEST account and `livemode=false` on the account Balance before its first write, with every created object still required to report `livemode=false`. The Starter price is now a disposable run-owned fixture: each checkout test creates a TEST product and $35 monthly price, proves them with the existing catalog readback, and archives both with readback, and the cleanup receipt requires those rows. The cleanup and readback rules for customers and Checkout sessions are unchanged. The B-068 verifier also stops passing vacuously outside Actions: its preflight checks now set `GITHUB_SHA`, so they reach the profile preflight and assert the exact refusal, and they no longer write fixture receipts into the repository tree.
