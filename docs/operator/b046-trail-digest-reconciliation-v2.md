It runs region-specific `aws cloudtrail validate-logs --trail-arn <approved-trail-arn> --region <approved-region> --start-time <probe-window-start-utc> --end-time <poll-time-utc> --verbose`, parses only exact `Log file s3://... valid` URIs, rejects any INVALID/gap, fetches a bounded number/size of candidate validated log files, and parses locally without printing raw payloads. It finds the `PutObject` from the distinct writer role/session and exact-version denied `DeleteObject` from the probe role/session for the same bucket/key/version; CloudTrail supplies event/request IDs (the normal S3 CLI response is not treated as their source). Accept only if each event's containing log URI is one of the validator's exact valid outputs and the covering digest chain has complete nonzero digest/log summaries. Record hashes of those log URIs and validation output in the final receipt; do not emit raw AWS payloads or unredacted account/bucket/key/version values. Timeout/missing event/missing digest/invalid chain leaves the artifact provisional and issue open; later reconcile of that same source run may be read-only, never a second probe.

Only after expiry and separately authorized legal-hold release may the exact-source-run cleanup path release the hold, delete the exact version, and delete the empty probe bucket.
